# GUI 设计原型（SVG 画布，先敲定长相，再接线）

用户的要求演进（2026-09-23）：

1. 「我希望可以先做 **web 版的拖拽元素**，可以让我把按钮等拽到合适位置，**按钮链接功能可以晚点做**，
   需要通过 web 让我敲定一个好看的 GUI」；
2. 试过第一版后用户觉得"CAD 更抽象"、提议「**要不还是 html 做的 SVG？**」—— 于是改成 **SVG 画布**：
   元件就是真实控件的模样（看得见、拖得准），画布尺寸 = 软件窗口外框（1440×900，1 单位 = 1 像素）。

所以这里**只有一个自包含的 HTML 文件**：`index.html`（双击打开，不装东西、不起服务、不联网）

## 怎么用

1. **双击 `index.html`** 用浏览器打开就行 —— 不需要装东西、不需要起服务、不联网也能开
   （字体/CSS/JS 全内联，没引任何外部资源）。
2. 右上角「预设布局」先选一个骨架（`左栏 + 主区` / `顶部工具条 + 主区` / `单列向导式` / `空白`）。
3. 从**左侧组件库**点一下就把元件加到画布中间；**拖动移动**（自动吸附 8px 网格，
   靠近别的元件边缘/中线会**贴上去并出红色参考线**）；右下角小方块**拉大小**；
   **方向键微调**（1 单位，`Shift` 一次 10）；`Delete` 删除、`Ctrl+Z` 撤销；工具栏能缩放/适应窗口。
4. 点中元件 → **右侧改文字 / X / Y / 宽 / 高**。
5. 想改哪儿就在右侧**备注**里写（比如「运行日志要能折叠」）。
6. 摆好之后点 **「就是它了（存下这版）」**，再点 **「导出布局」** 得到一个
   `wordfactory-gui-layout.json` —— **把这个 JSON（连同备注）发我**，我照它做真界面。

排版自动存在浏览器里（换页/重启还在），下次打开接着摆。

## 为什么用 SVG 而不是 div / CAD

| | div 拖拽 | CAD（DXF） | **SVG 画布** |
|---|---|---|---|
| 位置精度 | 受 CSS 布局影响，px 不直接 | 精确但要换算比例 | **1 单位 = 1 像素，直接就是界面坐标** |
| 所见即所得 | 一般 | 抽象（线框） | **元件画成真实控件的样子**（按钮/复选框/表格清单/预览窗都带内容） |
| 对齐辅助 | 要自己写 | 靠 CAD 的捕捉 | 吸附网格 + 边缘/中线参考线 |
| 交接格式 | JSON | DXF | **JSON（和工具链同一种）** |

DXF 方案 2026-09-23 试过一版（`wordfactory/dxf.py` + `dxf_layout.py`），用户看后觉得 CAD 太抽象，
**已撤掉**（代码、测试、发布件全删，git 历史里留痕）。

## 组件库对应的是真功能（不是随便摆的假按钮）

| 组件 | 对应工具箱里的东西 |
|---|---|
| 侧栏 / 标签页 | 各功能入口：宏库、表格款式、段落配方、规则文件、体检 |
| 主工作区 | 当前功能的界面（例如表格款式的模板选择 + 表格清单） |
| **表格清单** | `tablestyle list` 的真实输出：**按表头勾选**哪几张表要套模板（你要的那排复选框） |
| 模板选择器 | 6 个表格模板（外粗内细 / 全居中 / 均布列宽 / 自适应 / 三线表 / 三线表·均布） |
| 预览窗 | 套用后的样子（真做的时候是"先生成一份预览文档让你用 Word 看"） |
| 运行日志 | `--dry-run` 的报告：改了多少处、哪几类 |
| 动作按钮 | 运行（dry-run）/ 出验证版 / 出正式版 / 体检 AUDIT |

## 现在还没做的（**故意**的）

- **按钮不接线**：点了不会真的去改文档 —— 用户要求"按钮链接功能可以晚点做"，
  这一版只解决"**长什么样、元素怎么摆**"。
- 没有多页签切换、没有真实数据（表格清单里的表头是拿你报告的真实表头当样例）。

## 敲定之后我怎么做真界面

两种走法，等用户挑：

1. **本地网页界面**（推荐）：Python 起一个只监听 `127.0.0.1` 的小服务，页面就是这套布局，
   点按钮 = 调对应命令；好处是样式完全可控、跨平台、和 CLI 共用一套代码。
2. **Tkinter 原生窗口**：不用浏览器，但控件样式受限（做到"好看"更难）。

不管走哪条，**布局定稿的 JSON 就是施工图**：元素 → 控件、坐标 → 布局、备注 → 需求清单。
