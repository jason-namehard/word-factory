上下标字典（智能上下标）—— 直接在这里改，不用碰 JSON

逐字符（N/S/B）：左边写死一串字，右边逐个字符标格式 —— N 正常、S 上标、B 下标。 例：写 m2 + NS = m 正常、2 上标（最常用，字典里 20 多条都是这种）。
正则：左边写正则，右边选"整段匹配"或"第 1 捕获组" + 上标/下标。 例：写 m([2-9]+) + 第 1 捕获组 + 上标 = 任何 m2…m9 里的数字都上标。
两者的区别不是快慢：逐字符是"原文照着写死"，一个写法一条； 正则是"按模式找"，一类写法一条（适合 m 后跟任意数字这种）。两者都按**从上到下**的 顺序匹配，先匹配上的先处理、后面的规则不再动同一段字。
一串字符里多个上下标怎么办：逐字符方式把整串都写进去、逐个字母标，例如 Qpl + NBB = Q 正常、p 下标、l 下标。 只写一部分（如 mm2 + NNS）也可以，长度对得上就行。

这是什么

不依赖 Word/WPS/VBA 的 Word 文档批量规范化工具：直接读写 .docx 的 OOXML （zip + XML，只用 Python 标准库）。

推荐流程：顶栏导入报告（可多份）→「执行方案」页选/调方案（勾功能、排序、 指定前置区）→ 点「运行此方案」出临时版（标蓝，进临时文件夹）→ 满意后点顶栏 「出预览版」核对或直接「出正式版」（自动变黑 + 字体合规 + 体检）。

文件不会被覆盖：结果另存为「某报告（预览版）.docx /（正式版）.docx」。

体检 AUDIT = 重新打开写出的文件、独立复算"通体黑 + 字体合格"，末行 AUDIT=PASS/FAIL —— 正式版跑完自动做，不信工具自己的汇报。
